## ID76 最小覆盖子串 代码纠错（讲解，未改文件）

用户自己改写后仍有逻辑错误，逐条定位：

1. `curr[l]--` 用位置当下标，应为 `curr[sCharArray[l]]--`（`curr` 按字符编码索引）。
2. `r++; curr[r]++;` 顺序与下标都错：应先 `curr[sCharArray[r]]++` 再 `r++`；现在把位置当编码，r≥128 会 AIOOBE。
3. `while (r < len)` 结构会在 r 扩到 len 时直接退出，最后一个窗口（以及初始窗口）永不 check，如 s="ba",t="a" 返回 ""。
4. 初始化无 `t.length() > s.length()` 防护，示例3 `s="a",t="aa"` 越界。
5. `char[]` 计数器会溢出（m,n ≤ 1e5，char 上限 65535），应改 `int[128]`。
6. 性能：初始化里 `s.toCharArray()` 每轮复制整串，`sCharArray` 声明未用。

推荐结构：extend-then-shrink（外层 for 扩展右端，内层 while 合法即收缩并记录），可一次性消除上述结构性缺陷；`check` 用 have/need 可降到 O(1)。

### 第二次复查（用户改后）

用户已修正下标与 check 方向，但仍有致命边界：

- `while (r <= len)` 允许 r == len 进入循环，而 else 分支 `curr[sCharArray[r]]++` 未判 r == len，必然越界；`s="a",t="a"` 直接抛 AIOOBE。由于 r 单调增到 len 且退出前必走一次 else，**任何输入都会崩**。
- 最小修复：改 `while (true)` + else 开头 `if (r == len) break;`。
- 仍存在：`char[]` 计数溢出（应 int[]）、初始化 `s.toCharArray()` 每轮复制（应用 sCharArray）、每次收缩 `substring` 分配（应记 start/minLen）。
